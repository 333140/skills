# 合同审查技能

## 概述

本技能通过**仅添加批注**的方式执行合同审查（不修改原文内容）。遵循五层审核模型（合法性前置→基础→商业→法律→专项），生成以下内容：

- 带批注的合同文档 (.docx)
- 合同概要 (.docx)
- 综合审核意见 (.docx)（四段式结构）
- 业务流程图 (Mermaid + 渲染图片)

**v2.0.0 新增特性：**
- Layer 0 合法性前置审查（6项必查）
- 合同类型自动识别与差异化检查（8种类型 + 涉外专项）
- 强制法律免责声明
- 检查项优先级体系（P0/P1/P2）
- 电子合同合规检查
- 大型文档分段处理策略
- 版本管理与审计轨迹

**语言规则：** 自动检测合同的主要语言，所有生成内容（批注、概要、意见、流程图文本）均使用该语言输出。请参考 **[references/language.md](references/language.md)** 中的指导。

## 工作流程

1. **自动检测输入格式** (.docx 或 .pdf)
   - 如果是PDF：使用pdfplumber提取文本（通过PDF Processing Pro技能）
   - 如果是DOCX：解包进行XML操作
2. 读取合同文本（使用pandoc、XML或pdfplumber）
3. **合同类型识别**（新增步骤，在五层审核前执行）
   - 根据关键词和结构特征判断合同类型，加载对应的差异化检查项：

   | 合同类型 | 识别关键词示例 | 激活附加检查项 |
   |--------|-------------|-------------|
   | 买卖合同 | 购买、出售、货款、验货、发货 | 质量标准、所有权转移时点、货款结算方式 |
   | 服务合同 | 提供服务、服务费、服务期限、服务内容 | 服务验收标准、人员资质、成果归属 |
   | 劳动合同 | 劳动者、用人单位、试用期、社会保险 | 法定必备条款（《劳动合同法》第17条）、试用期上限、竞业限制36个月上限 |
   | 保密协议 | 保密信息、保密义务、商业秘密 | 保密范围是否过宽致无效、接收方身份、泄露救济措施 |
   | 技术合同 | 技术开发、技术转让、专利、著作权 | 技术成果归属、职务发明判断、技术出口管制 |
   | 建设工程合同 | 工程承包、施工、竣工、质保金 | 质保金比例（≤5%）、工程款支付节点、竣工验收程序 |
   | 涉外合同 | foreign、international、跨境、境外方 | 激活 **[涉外合同专项检查]**（见下文） |
   | 数据/隐私合同 | 个人信息、数据处理、数据安全 | 《个保法》合规条款、数据跨境传输、安全评估义务 |

   - 识别后在审核发现预览中增加一行：
     ```
     合同类型识别：[买卖合同 / 服务合同 / 劳动合同 / ……]
     差异化检查项：已加载 [N] 个附加项目
     ```
   - 若无法确定类型，默认执行通用清单并提示：`合同类型：未能明确识别，执行通用检查项`

   **涉外合同专项检查（附加层）：** 当识别为涉外合同时，在五层审核完成后追加以下检查：

   | # | 检查项 |
   |---|--------|
   | F.1 | 法律适用是否明确排除 CISG（联合国国际货物销售合同公约）——未明确排除时自动适用 |
   | F.2 | 争议解决是否选择国际仲裁机构（ICC、HKIAC、SIAC 等）及适用的仲裁规则 |
   | F.3 | 外汇支付条款是否符合国家外汇管理局监管要求 |
   | F.4 | 是否涉及出口管制商品或技术（商务部《出口管制法》） |
   | F.5 | 香港/澳门法律适用是否明确区分内地法与港澳法 |
   | F.6 | 合同语言版本以哪个为准，是否有双语版本冲突风险 |

4. **执行五层审核**（Layer 0 合法性前置 → Layer 1 基础 → Layer 2 商业 → Layer 3 法律 → 专项检查）
5. **检查点1 — 审核发现预览**
   - 在添加任何批注前，向用户展示摘要：
     ```
     ⚠️ 合法性前置审查：发现 [N] 个潜在效力瑕疵问题（见批注）
     合同类型识别：[买卖合同 / 服务合同 / ……]
     差异化检查项：已加载 [N] 个附加项目
     🔴 高风险问题：X 个（不含 Layer 0）
     🟡 中风险问题：Y 个
     🔵 低风险/建议：Z 个
     总计：N 个问题
     ```
   - 询问用户："是否继续添加批注到文档？" (是/否/跳过低风险)
   - 如果用户选择"跳过低风险" → 仅添加 🔴 和 🟡 级批注，以及 P0 和 P1 优先级批注
   - 如果用户选择"否" → 仅输出文本报告，跳过批注添加
6. 根据检查点决策向文档添加批注
7. 生成合同概要
8. 生成综合审核意见（四段式）
9. 生成业务流程图并渲染图片
10. 重新打包为.docx

## 输出命名规则

- 输出目录：中文为 `审核结果：{ContractName}`，英文为 `Review_Result_{ContractName}`
- 审核版合同：中文为 `{ContractName}_审核版.docx`，英文为 `{ContractName}_Reviewed.docx`
- 审核报告：中文为 `审核报告.txt`，英文为 `Review_Report.txt`
- 输出文件名中嵌入审核日期，便于区分多轮修订版本：
  - `{合同名称}_审核版_20250523.docx`
  - `{合同名称}_审核版_20250528_v2.docx`

## 免责声明（强制输出）

**所有输出文件必须在首页或批注说明区域包含以下文本，不得省略：**

> 本审查报告由 AI 辅助生成，仅供参考，不构成法律意见，不能替代具有执业资质的律师对具体合同的专业审查。
> 合同的最终法律效力判断及签署决策，应由当事人自行负责或咨询专业法律顾问。

**批注文件实施方式：** 在 Word 文档第一页页眉或正文开头插入一个独立"审查说明"段落（样式：楷体、9pt、灰色），包含上述声明。

**概要/意见文件实施方式：** 作为文档最后一节"注意事项"单独列出。

## 批注原则

- **仅添加批注**：不修改原文内容或格式
- **精确定位**：批注应针对具体条款/段落
- **结构化内容**：每个批注包含问题类型、风险原因和修改建议
- **风险等级**：通过审阅者名称编码；**不要**在批注正文中包含"风险等级"行
- **输出语言**：使用合同语言的标签（请参考 `references/language.md`）

**批注示例（英文）：**
```
[问题类型] 付款条款
[风险原因] 第3.2条 stated 总金额为USD 100,000，但付款条款第5.1条列出USD 1,000,000。这种不一致可能导致争议。
[修改建议] 统一各条款中的总金额，并明确是否包含税费。
```

## 审核标准

使用五层审核模型，并参考 **[references/checklist.md](references/checklist.md)** 中的详细检查清单。

### Layer 0: Legal validity（合法性前置审查）— 必查 6 项

> 本层检查条款是否触及法律强制性规定或违反公序良俗，凡命中均为 🔴 高风险。

| # | 检查项 | 法律依据 | 风险后果 |
|---|--------|---------|---------|
| 0.1 | 合同主体是否具备相应民事行为能力或经营资质 | 《民法典》第143条 | 合同无效 |
| 0.2 | 是否存在意思表示不真实（欺诈、胁迫、重大误解）的明显迹象 | 《民法典》第147-151条 | 可撤销 |
| 0.3 | 是否包含排除对方主要权利的格式条款（如"最终解释权归本公司"） | 《民法典》第497条 | 格式条款无效 |
| 0.4 | 违约金条款是否存在显著不对等（一方违约金远超另一方） | 《民法典》第585条 | 可申请调整 |
| 0.5 | 是否违反法律、行政法规的强制性规定 | 《民法典》第153条 | 合同无效 |
| 0.6 | 是否违背公序良俗 | 《民法典》第153条第2款 | 合同无效 |

**检查点说明：** Layer 0 命中项目必须在审核预览中单独列出，并置于所有其他风险发现之前，格式如下：
```
⚠️ 合法性前置审查：发现 [N] 个潜在效力瑕疵问题（见批注）
🔴 高风险问题：X 个（不含 Layer 0）
……
```

### Layer 1: Basic (text quality) — 必查 8 项
| # | 检查项 | 搜索关键词示例 |
|---|--------|---------------|
| 1.1 | 合同编号是否填写 | "合同编号"、"协议编号" |
| 1.2 | 签署日期是否完整 | "签署日期"、"签订日期"、"生效日期" |
| 1.3 | 当事人信息是否完整（名称、身份证号/统一社会信用代码、地址） | "甲方"、"乙方"、"身份证号" |
| 1.4 | 金额数字前后一致（大小写、各条款间） | "¥"、"人民币"、"元" |
| 1.5 | 日期/期限计算正确（起止日、工作日 vs 自然日） | "年"、"月"、"日"、"工作日" |
| 1.6 | 条款编号连续无跳跃 | "第X条"、"X.X" |
| 1.7 | 术语定义前后一致 | 合同中首次出现的专业术语 |
| 1.8 | 空白字段/下划线是否已填写 | "_____"、"……"、"待定" |

### Layer 2: Business terms — 优先级修订版

> **优先级说明：** P0 = 必须出具批注；P1 = 有问题时出具批注；P2 = 建议性提示，可在"跳过低风险"模式下省略

| # | 检查项 | 优先级 | 中国司法实践依据 |
|---|--------|-------|--------------|
| 2.1 | 标的/服务范围描述清晰无歧义 | **P0** | 范围不清是合同纠纷第一大成因 |
| 2.2 | 价格与付款条件明确（总价、单价、付款节点、发票类型） | **P0** | 金额不一致、付款节点模糊属高频争议 |
| 2.3 | 交付/验收标准可执行 | **P0** | 验收标准不明确导致无法主张违约 |
| 2.4 | 权利义务对等（双方责任平衡） | **P1** | 需结合具体条款判断，非必然问题 |
| 2.5 | 变更/解除条件合理 | **P1** | 常见于长期合同，短期合同可降级 |
| 2.6 | 保密义务范围与期限适当 | **P1** | 范围过宽影响员工离职及竞业 |
| 2.7 | 知识产权归属明确 | **P0** | 技术类合同必查，其他合同 P1 |
| 2.8 | 不可抗力条款完整 | **P2** | 标准条款，仅在缺失时提示 |

### Layer 3: Legal terms — 优先级修订版

| # | 检查项 | 优先级 | 中国司法实践依据 |
|---|--------|-------|--------------|
| 3.1 | 法律适用与管辖明确 | **P0** | 管辖争议是诉讼前置障碍，必查 |
| 3.2 | 违约责任对等且可执行（违约金不过高/过低） | **P0** | 违约金调整是最高院常见裁判事项 |
| 3.3 | 争议解决方式具体（仲裁机构/管辖法院） | **P0** | 仲裁条款无效（机构名称错误）极为常见 |
| 3.4 | 通知送达条款完整（地址、方式、生效时点） | **P1** | 涉诉时影响送达生效，不涉诉时次要 |
| 3.5 | 合同生效条件明确（签字盖章/附条件/附期限） | **P0** | 附条件生效未满足时合同不成立 |
| 3.6 | 担保/保证条款合法（如适用） | **P0** | 仅适用于含担保条款的合同，否则跳过 |
| 3.7 | 竞业限制/排他条款合理（如适用） | **P0** | 劳动合同必查；期限>2年视为无效 |
| 3.8 | 附件/补充协议清单完整 | **P2** | 整体性检查，优先级较低 |

**Risk levels (encoded in reviewer name):**
- 🔴 High: core business ambiguity (price, scope, rights/obligations)
- 🟡 Medium: material but non-core ambiguity
- 🔵 Low: minimal practical impact

## 审核报告渲染器

如果需要专业格式的DOCX审核报告（例如从带有emoji风险标记的AI生成Markdown），请使用：

```bash
python scripts/report_renderer.py input.md -o output.docx -t "合同审核报告" -c "合同名称"
```

功能特性：
- 将emoji风险标记（🔴🟡🔵）替换为彩色粗体文本标签
- 专业排版：黑体标题，宋体正文，楷体强调文本
- 合同信息表格，金色分隔线，带页码的页眉/页脚
- 解析Markdown标题、列表、粗体文本和水平线

## PDF支持

如果用户上传PDF合同，技能将自动：
1. 使用`pdfplumber`提取文本（通过PDF Processing Pro技能）
2. 对提取的文本执行五层审核
3. 生成概要、意见和流程图（与DOCX工作流程相同）
4. **注意**：PDF输入无法生成带批注的.docx文件；输出仅为概要+意见+流程图+文本报告。

要将PDF转换为DOCX以实现完整批注工作流程，请使用：
```bash
python scripts/pdf_to_docx.py input.pdf output.docx
```

## 错误处理与回退机制

### PDF文本提取失败
```
如果pdfplumber失败或返回空文本：
  1. 使用PyPDF2作为回退机制重试
  2. 如果仍然为空 → 提示用户："PDF 无法自动提取文本，请粘贴合同内容或转换为 Word 后重试"
  3. 永远不要静默跳过 — 总是告知用户问题并提供替代方案
```

### Mermaid渲染失败
```
如果mmdc未安装或渲染失败：
  1. 保存.mmd源文件（总是保存）
  2. 告知用户："流程图源码已保存，可手动渲染或安装 mmdc: npm i -g @mermaid-js/mermaid-cli"
  3. 继续工作流程 — 不要阻塞其他输出
```

### 依赖项缺失
```
如果pandoc / python-docx / defusedxml未找到：
  1. 告知用户确切的缺失依赖项
  2. 提供安装命令（pip install xxx 或 apt/brew install）
  3. 如果是关键依赖项（DOCX输入的pandoc），停止并等待用户操作
  4. 如果是非关键依赖项（mmdc），继续 degraded 输出
```

### 空或损坏的合同
```
如果提取的文本少于50个字符：
  1. 告知用户："合同内容异常短，可能为扫描件图片或加密 PDF"
  2. 建议："请尝试直接粘贴文本，或使用 OCR 工具"
  3. 不要继续审核 — 垃圾输入，垃圾输出
```

## 故障排除（简版）

- **Word中批注缺失**：运行 `doc.verify_comments()` 并重新保存
- **find_paragraph失败**：缩短搜索文本；确认实际段落文本
- **Mermaid渲染失败**：确保`mmdc`已安装；使用Chrome路径或Puppeteer配置

## 电子合同合规检查（新增）

当检测到合同为电子格式（PDF 含电子签名元数据、或合同文本中出现"电子签名"、"数字证书"等词汇）时，追加以下检查：

| # | 检查项 | 法律依据 |
|---|--------|---------|
| E.1 | 电子签名是否符合可靠电子签名条件（唯一性、可验证、防篡改） | 《电子签名法》第13条 |
| E.2 | 电子签名服务提供商是否为经认证的第三方（如法大大、e签宝） | 《电子签名法》第18条 |
| E.3 | 合同是否属于不得使用电子签名的类型（婚姻、收养、不动产、公用事业） | 《电子签名法》第3条 |
| E.4 | 电子合同存储与归档方式是否有明确约定 | GB/T 38540-2020 |

## 大型文档分段处理策略（新增）

当合同篇幅超过 50 页时，执行以下分段策略：

```
LARGE_CONTRACT_THRESHOLD = 50  # 页数
CHUNK_SIZE = 15                 # 每段处理页数
OVERLAP_PAGES = 2               # 段间重叠页数（防止条款被截断）
```

处理流程：
1. 按章节结构分段（优先按"第X章"或"第X条"边界切割，而非按固定页数）
2. 每段独立执行五层审核
3. 跨段一致性检查（金额、日期、当事人名称是否前后一致）
4. 合并审核结果，去重相同问题
5. 在审核报告首页注明："本合同因篇幅较大，已分 [N] 段处理，跨段一致性已独立验证"

## 重要规则

1. 永远不要修改原文合同内容
2. 审核所有五层（Layer 0 → Layer 1 → Layer 2 → Layer 3 → 专项），不要跳过任何项目
3. Layer 0 命中项目必须单独列出，置于所有其他风险发现之前
4. 确保风险等级准确且一致
5. 保持批注精确、专业且可操作
6. 流程图必须严格基于合同文本
7. 概要仅包含客观信息；不包含风险分析
8. 意见采用四段式结构，仅反映已识别的发现
9. 所有输出文件必须包含强制法律免责声明
10. 合同类型识别后必须加载对应的差异化检查项
